# 多笼合并纪要（当日锁死）

- 日期：2026-11-22
- 范围：保证金笼母仓，同合约（同 `party_key` + 同 `contract_no`）多只已冻结笼合并为一只主笼
- 库路径：`data/app.db` 不变；前端导航会话保留（不新增/删减导航页，合并写口落在「入笼冻结」页）

## 一、正确性口径（二选一，两边不得混用）

本仓当日锁死走 **甲路径：合并整笔同事务**。

1. 同一提交（单事务）内：
   1. 作废全部来源笼（状态置 `已合并作废`，笼行保留可审计，可用额归零）；
   2. 金额累加写入主笼（`amount`/`available` 同额累加，笼代 `generation` 加 1）；
   3. 重算账户冻结（以全部活笼可用合计为准回写 `bond_accounts.frozen`，余额不动）；
   4. 写审计（`cage_merge`）与合并血缘（`merge_jobs` / `merge_lineage`）。
2. 任一步失败：作废与累加同滚（事务整体回滚），来源笼、主笼、账户冻结、审计均零改。
3. 并发：同一当事人的合并须抢账户锁 `bond:{party_key}`；后到者只留 `contention_log` 争用痕，业务零写、返回 409。

**乙路径（桥接影子主笼 → 确认后原子晋升）本仓禁用。** 任何请求声明 `mode=影子晋升` 或夹带影子笼状态，按「合并偏航」拒写并记审计 `merge_yaw`，返回 409。甲、乙两套写口不得在同一服务内并存。

## 二、合并准入（偏航即拒写）

- 主笼与全部来源笼必须：同当事人、同合约号、状态均为 `已冻结`；
- 不允许纳入已有核验结论、已部分解笼/罚没、已作废、影子态的笼；
- 至少 1 只来源笼；来源笼与主笼不得重复；
- 主笼累加后金额须等于各笼原金额之和（6 位小数口径），否则整笔回滚。

## 三、账实同源（五页）

入笼页、账户页、对账页、核验页、审计页共用同一 SQLite 库与同一状态口径：

- 活笼状态集合 = `已冻结 / 核验通过 / 核验违约 / 部分解笼 / 部分罚没`；
- 作废笼不参与活笼冻结合计，对账页单列「已合并作废」血缘行，不计失衡；
- 账户冻结恒等式：`bond_accounts.frozen == SUM(活笼.available)`，合并事务内强制校验，不平即回滚。

## 四、偏离处置

- 与本纪要口径不符的写请求 → 记 `merge_yaw` 审计并 HTTP 409 拒写；
- 禁止只改入笼页合并按钮文案而不落写口；
- 失败测未红前禁止改入笼/账户/对账/核验服务与入笼页、对账页。
